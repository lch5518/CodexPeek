# CodexPeek 계정 및 인증 정보 저장 구조

이 문서는 CodexPeek의 여러 사용량 프로필이 어떤 정보를 어디에 저장하는지 설명합니다.
CodexPeek의 프로필은 **사용량 조회와 표시 대상을 분리하기 위한 기능**이며, 터미널·IDE·Codex
앱의 로그인 계정을 전환하는 기능이 아닙니다.

## 저장 위치 요약

```text
%APPDATA%\CodexPeek\
├─ settings.json
└─ profiles\
   ├─ profile-0001\
   │  └─ codex-home\
   │     └─ auth.json       # Codex CLI가 생성하고 사용하는 인증 파일
   └─ profile-0002\
      └─ codex-home\
         └─ auth.json
```

Installer와 Portable 배포판 모두 같은 사용자 데이터 루트를 사용합니다. 프로필 표시명은 경로에
사용하지 않으며, 검증된 내부 숫자 ID로 `profile-0001` 같은 디렉터리를 만듭니다.

## CodexPeek가 직접 저장하는 정보

`%APPDATA%\CodexPeek\settings.json`에는 UI 설정과 다음 프로필 카탈로그 정보만 저장합니다.

- 사용자가 직접 입력한 프로필 표시명
- 선택 사항인 시스템 프로필 표시명(`system_label`)
- 내부 숫자 순번
- 현재 CodexPeek에 표시할 프로필
- 다음 프로필을 만들 때 사용할 순번

형태는 다음과 같습니다. 실제 파일에는 다른 CodexPeek UI 설정도 함께 들어갑니다.

```json
{
  "usage_profiles": {
    "system_label": "Main",
    "managed": [
      { "sequence": 1, "label": "Work" }
    ],
    "selected": "system",
    "next_sequence": 2
  }
}
```

CodexPeek는 계정 이메일, OpenAI 계정 ID, 액세스 토큰, 갱신 토큰 또는 원본 RPC 응답을
`settings.json`에 저장하지 않습니다. 표시명은 계정에서 읽어 온 값이 아니라 사용자가 정한 별칭입니다.
따라서 서로 다른 표시명의 프로필에 같은 브라우저 계정으로 로그인했는지 자동으로 판별하지 않습니다.
`system_label`은 선택 사항인 사용자 제공 표시 메타데이터이며, 없으면 기존 기본 시스템 이름을
사용하므로 이전 `settings.json` 파일과 호환됩니다. 이 값은 계정 식별자가 아니며 `CODEX_HOME` 또는
인증 파일을 변경하지 않습니다.

## Codex CLI가 저장하는 인증 정보

관리 프로필에서 로그인을 시작하면 해당 프로필용 자식 `codex app-server` 프로세스에만 다음 값을
전달합니다.

```text
CODEX_HOME=%APPDATA%\CodexPeek\profiles\profile-0001\codex-home
-c cli_auth_credentials_store=file
```

인증 파일은 이 격리된 Codex 홈 안에서 **Codex CLI가 생성하고 사용**합니다. 현재 파일 저장소에서는
일반적으로 `auth.json`이 사용되지만, 파일의 형식과 내용은 Codex CLI의 책임입니다. CodexPeek는 시스템
프로필 또는 관리 프로필의 `auth.json`을 열거나 읽거나 파싱하거나 복사하지 않습니다.

CodexPeek는 이 파일에 별도 암호화를 추가하지 않습니다. 따라서 관리 프로필 디렉터리는 민감한 사용자
데이터로 취급해야 하며, 실제 저장 보호 수준은 Codex CLI의 파일 형식과 Windows 사용자 계정의 파일
권한에 의존합니다. 같은 Windows 사용자 권한으로 실행되는 악성 프로그램이나 관리자는 이 격리를 보안
샌드박스로 간주해서는 안 됩니다.

## 시스템 프로필

삭제할 수 없는 시스템 프로필은 CodexPeek가 시작할 때 상속한 `CODEX_HOME`을 사용합니다. 해당 환경
변수가 없으면 설치된 Codex CLI의 기본 홈을 사용합니다. 이름은 바꿀 수 있지만 로그아웃하거나 삭제할
수는 없습니다. 사용자 지정 이름은 CodexPeek 표시용 메타데이터일 뿐이며 계정 식별자가 아닙니다.
시스템 프로필에는 별도의 `CODEX_HOME`이나 파일 인증 저장소 옵션을 주입하지 않으며 기존 인증 파일을
새 CodexPeek 디렉터리로 복사하지 않습니다.

## 터미널과 IDE에 영향이 없는 이유

관리 프로필의 `CODEX_HOME`은 해당 사용량 조회용 자식 프로세스에만 설정합니다. CodexPeek 자신의 환경,
Windows 사용자·시스템 환경 변수, `PATH`, 터미널, IDE, Codex 앱, WSL, Remote SSH 또는 Dev Container의
로그인 상태는 변경하지 않습니다. 프로필 선택도 수동이며 사용량에 따른 자동 선택이나 순환은 없습니다.

## 사용량 데이터와 진단 로그

프로필별 최근 사용량, 재시도 상태와 마지막 정상 결과는 실행 중 메모리에 유지합니다. 종료 후 다시
시작하면 Codex CLI RPC로 새로 조회합니다. 안전 진단에는 구성됨·정상·로그인 필요·요청 실패 프로필의
제한된 집계 개수만 기록합니다.

다음 값은 진단 로그와 사용자 오류에 기록하지 않습니다.

- 프로필 표시명과 내부 ID
- 관리 프로필 경로
- 계정 이메일과 계정 ID
- 인증 파일 내용과 토큰
- 원본 RPC payload

## 기존 데이터 경로 마이그레이션

이전 버전은 `%APPDATA%\CodexUsageMonitor`를 사용했습니다. 새 버전은 시작할 때 다음 규칙을 적용합니다.

1. `%APPDATA%\CodexPeek`가 이미 있으면 새 경로를 사용하고 이전 경로를 덮어쓰거나 병합하지 않습니다.
2. 새 경로가 없고 이전 디렉터리만 있으면 같은 부모 디렉터리 안에서 디렉터리 전체를 원자적으로
   `%APPDATA%\CodexPeek`로 이동합니다.
3. 이 이동은 인증 파일을 열거나 복사하지 않고 디렉터리 이름만 변경합니다.
4. 이동에 실패하면 데이터를 잃지 않도록 그 실행에서는 이전 경로를 계속 사용하며 다음 시작 때 다시
   이전을 시도합니다.

두 경로가 모두 존재하는 경우 자동 병합은 데이터와 인증 정보 충돌 위험 때문에 수행하지 않습니다.
필요한 데이터를 확인하기 전에는 이전 디렉터리를 수동으로 삭제하지 마세요.

## 프로필 삭제

관리 프로필 삭제는 다음 순서로 처리합니다.

1. 해당 프로필의 사용량 조회와 로그인 작업을 중단합니다.
2. 정확히 검증된 프로필 디렉터리를 같은 볼륨의 내부 tombstone 이름으로 이동합니다.
3. 프로필을 제거한 설정을 원자적으로 저장합니다.
4. 설정 저장이 성공한 뒤 tombstone을 삭제합니다.

설정 저장이 실패하면 원래 디렉터리로 복원합니다. 저장 이후 최종 정리만 실패한 경우 다음 시작 때
검증된 tombstone을 정리합니다. 삭제가 완료되면 격리된 Codex 홈과 그 안의 Codex CLI 인증 정보는
복구할 수 없으므로 UI에서 명시적 확인을 요구합니다. 시스템 프로필은 삭제할 수 없습니다.

## 설정 손상 백업

잘못된 `settings.json`은 같은 데이터 루트 아래에 `settings.corrupt-*.json` 형태로 백업될 수 있습니다.
이 백업에는 사용자가 입력한 프로필 표시명과 UI 설정이 포함될 수 있지만, 관리 프로필의 인증 파일
내용은 포함되지 않습니다.
