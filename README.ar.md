# Codex Usage Monitor

**Languages:** [English (default)](README.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Português (Brasil)](README.pt-BR.md) · [Bahasa Indonesia](README.id.md) · [日本語](README.ja.md) · [हिन्दी](README.hi.md) · [Deutsch](README.de.md) · [Français](README.fr.md) · [Tiếng Việt](README.vi.md) · [Türkçe](README.tr.md) · [العربية](README.ar.md)

Codex Usage Monitor هو ويدجت Windows أصلي صغير للتحقق من استخدام Codex بنظرة سريعة.
يعرض نوافذ حدود المعدل الأساسية والثانوية في شريط المهام، وويدجت عائم، وعلبة النظام.

![ويدجت Codex Usage Monitor في شريط المهام](docs/images/taskbar-widget-en.png)

## أبرز الميزات

- يعرض نوافذ استخدام Codex الأساسية والثانوية، بما في ذلك أوقات إعادة التعيين.
- يستخدم واجهة `app-server` في Codex CLI المثبتة بدلا من تحليل ملفات المصادقة.
- يدعم عرض الويدجت على كل أشرطة المهام أو على الشاشة الأساسية فقط.
- يعود بأمان إلى ويدجت عائم وأيقونة علبة النظام عندما لا يكون الإرفاق بشريط المهام متاحا.
- يدعم التحديث اليدوي، وفواصل التحديث التلقائي، وبدء التشغيل مع Windows، والتشخيصات، وواجهة مستخدم مترجمة.

## طريقة العمل

يشغل المراقب الأمر `codex app-server --stdio` كعملية فرعية محلية ويتبادل رسائل JSONL عبر الإدخال والإخراج القياسيين.
تتولى Codex CLI المثبتة مصادقتها بنفسها، وقد تتصل بـ OpenAI ضمن إعداداتها الحالية وسياسة الشبكة القائمة.

لا يطلب المراقب إلا حالة تسجيل الدخول ونوافذ الاستخدام اللازمة للعرض.
ولا يبدأ مهمة Codex أو يستدعي `codex exec`.

## المتطلبات

- Windows 10 أو Windows 11، بمعمارية x64.
- [Codex CLI](https://github.com/openai/codex) مسجل الدخول ويدعم `account/read` و `account/rateLimits/read`.

## التنزيل والتشغيل

تحقق أولا من أن Codex CLI مثبتة وأن تسجيل الدخول نشط:

```powershell
codex --version
codex login status
```

### برنامج التثبيت (موصى به)

1. نزل `CodexPeek-Setup-v<version>-x64.exe` من
   [أحدث GitHub Release](https://github.com/lch5518/CodexPeek/releases/latest).
2. شغل برنامج التثبيت واتبع التعليمات. لا يلزم وصول المسؤول.
3. شغل **Codex Usage Monitor** من قائمة Start.

### النسخة المحمولة

1. نزل `codex-peek-v<version>-windows-x86_64-portable.zip` من أحدث إصدار.
2. استخرج ملف ZIP بالكامل إلى مجلد قابل للكتابة.
3. شغل `codex-peek.exe` من المجلد المستخرج.

### البناء من المصدر

يتطلب هذا الخيار Rust 1.85 أو أحدث، و Visual Studio 2022 C++ Build Tools، و
Windows SDK. يشغل التطبيق من المستودع المستنسخ ولا ينشئ اختصارا في قائمة Start
أو أداة إزالة تثبيت.

```powershell
git clone https://github.com/lch5518/CodexPeek.git
Set-Location .\CodexPeek
cargo build --release
.\target\release\codex-peek.exe
```

للتحقق من البناء واتصال Codex CLI من دون فتح واجهة المستخدم:

```powershell
.\target\release\codex-peek.exe --diagnose
```

### اطلب من Codex تثبيته

انسخ الموجه أدناه إلى Codex. يفضل برنامج التثبيت الذي تم التحقق منه، ولا يعود إلى
البناء من المصدر إلا عندما لا تتوفر أصول Release متوافقة.

```text
ثبت CodexPeek على هذا الكمبيوتر بنظام Windows x64 وأكمل التحقق نيابة عني.

1. أكد أن هذا النظام Windows x64، ثم شغل `codex --version` و `codex login status`.
2. استخدم المستودع الرسمي و Releases الخاصة به فقط:
   https://github.com/lch5518/CodexPeek
3. فضل أحدث ملف `CodexPeek-Setup-v<version>-x64.exe`. نزله مع
   `SHA256SUMS.txt`، واعثر على إدخال Installer المطابق تماما في ذلك الملف، واحسب
   SHA-256 الخاص بملف Installer، ولا تتابع إلا إذا تطابقت قيم التجزئة. لا تعطل
   عناصر التحكم الأمنية ولا تشغل ملفا تكون قيمة التحقق الخاصة به مفقودة أو مختلفة.
4. ثبته للمستخدم الحالي من دون طلب وصول المسؤول. حافظ على إعدادات CodexPeek
   الحالية ولا توقف تطبيقا قيد التشغيل أو عملية غير ذات صلة؛ أخبرني إذا كان علي
   إغلاق التطبيق بنفسي.
5. فقط إذا لم تكن أصول Release المتوافقة متاحة، فاستنسخ المستودع الرسمي في دليل
   جديد قابل للكتابة من قبل المستخدم وشغل `cargo build --release`. إذا كان يجب
   تثبيت Git أو Rust 1.85+ أو Visual Studio 2022 C++ Build Tools أو Windows SDK،
   فاشرح أولا بالضبط ما الذي سيتغير واطلب موافقتي.
6. لا تقرأ أو تطبع أبدا محتويات `%USERPROFILE%\.codex\auth.json`. يجب التعامل مع
   المصادقة فقط عبر Codex CLI المثبتة.
7. بعد التثبيت أو البناء، شغل `codex-peek.exe --diagnose` الناتج. إذا نجح،
   فشغل CodexPeek.
8. أبلغني بطريقة التثبيت المختارة، والإصدار المثبت، وموقع الملف التنفيذي، ونتيجة
   قيمة التحقق، ونتيجة التشخيص. إذا فشل أي شيء، فتوقف بأمان واشرح العائق الدقيق
   من دون كشف معلومات حساسة.
```

تستخدم نسختا برنامج التثبيت والنسخة المحمولة `%APPDATA%\CodexUsageMonitor\settings.json`، لذلك
تكون الإعدادات مشتركة إذا انتقلت بينهما. يضيف برنامج التثبيت اختصارا في قائمة Start
لكنه لا يفعل بدء التشغيل مع Windows افتراضيا.

الإصدارات الأولى غير موقعة برمز وقد تؤدي إلى ظهور تحذير Microsoft Defender SmartScreen.
نزل فقط من الإصدار الرسمي وتحقق من الملف مقابل `SHA256SUMS.txt`.

راجع [دليل التثبيت التفصيلي (بالكورية)](docs/INSTALL.md) للتحقق من التجزئة،
والتحديثات، وسلوك إزالة التثبيت، والتشخيصات، واستكشاف الأخطاء وإصلاحها.

## استخدام المراقب

استخدم قائمة علبة النظام لتحديث الاستخدام، واختيار فاصل تحديث من 1/5/10/15/30 دقيقة، وإظهار الويدجت أو إخفائه.
وتوفر أيضا إعدادات بدء التشغيل مع Windows، وطريقة العرض عند البدء، وتحديث المصادقة، وتحديث المصادقة التلقائي، واللغة، والتشخيصات.
اختر **Widget: all monitors** أو **Widget: primary monitor only** للتحكم في موضع الويدجت مع عدة شاشات؛ ويتم تذكر الاختيار عبر عمليات إعادة التشغيل.

افتراضيا، تتبع لغة واجهة المستخدم إعداد لغة Windows عندما تطابق إحدى اللغات المدعومة. يمكنك أيضا اختيار اللغة يدويا من قائمة علبة النظام. اللغات المدعومة هي الكورية، والإنجليزية، والإسبانية، والبرتغالية البرازيلية، والإندونيسية، واليابانية، والهندية، والألمانية، والفرنسية، والفيتنامية، والتركية، والعربية.

يستخدم ويدجت شريط المهام سمة Windows الفاتحة/الداكنة للنص، ويترك مادة شريط المهام الأصلية ظاهرة عبر الخلفية.

لا يعمل إلا طلب استخدام واحد في كل مرة. يعاد تنفيذ الطلبات الفاشلة بتأخيرات متزايدة بينما تبقى آخر القيم الناجحة مرئية.

إذا تعذر إرفاق ويدجت شريط المهام بعد إعادة تشغيل Explorer أو تغيير تخطيط شريط المهام، فتبقى أيقونة علبة النظام متاحة ويعيد المراقب المحاولة بأمان.

## الخصوصية والأمان

لا يقرأ المراقب محتويات `%USERPROFILE%\.codex\auth.json` ولا يحللها أبدا.
تتحقق التشخيصات فقط مما إذا كان هذا المسار موجودا.

تعالج استجابات RPC الخام فقط للمدة اللازمة لاستخراج نوع تسجيل الدخول وحقول حدود المعدل المعروضة.
لا يتم تخزين الرموز، أو معرفات الحساب، أو عناوين البريد الإلكتروني، أو محتويات ملف المصادقة، أو قيم الوكيل، ولا تكتب في السجلات.

تخزن الإعدادات في `%APPDATA%\CodexUsageMonitor\settings.json`.
ويخزن سجل تشخيص محدود في `%TEMP%\codex-peek.log`.

للاطلاع على إرشادات معالجة البيانات والإبلاغ عن الثغرات كاملة، راجع [SECURITY.md](SECURITY.md).

## استكشاف الأخطاء وإصلاحها

| المشكلة | ما يجب فعله |
| --- | --- |
| تعذر العثور على Codex CLI | شغل `codex --version` و `where.exe codex`، ثم تأكد من أن Codex CLI موجودة في `PATH`. |
| CLI غير مدعومة | حدث Codex CLI. دعم RPC المطلوب أهم من رقم الإصدار المعروض. |
| تم تسجيل الخروج أو انتهت صلاحية المصادقة | أكمل مسار تسجيل الدخول المعتاد في Codex CLI، ثم اختر **Refresh authentication** من قائمة علبة النظام. |
| ويدجت شريط المهام على الشاشة الخطأ | اختر **Widget: all monitors** أو **Widget: primary monitor only** من قائمة علبة النظام. |
| ويدجت شريط المهام مفقود | استخدم الويدجت العائم أو أيقونة علبة النظام، وأعد تشغيل Explorer عند الحاجة، ثم حدد وضع شاشة الويدجت المفضل. |
| يلزم مزيد من التفاصيل | شغل `--diagnose` أو افتح **Diagnostics** من قائمة علبة النظام. |

## التطوير

تتطلب عمليات البناء من المصدر Rust 1.85 أو أحدث، و Visual Studio 2022 C++ Build Tools، و
Windows SDK. ابن وتحقق من جذر المستودع:

```powershell
git clone https://github.com/lch5518/CodexPeek.git
Set-Location .\CodexPeek
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets
cargo build --release
```

لا تغني الفحوصات الآلية عن سيناريوهات Windows و DPI والشاشات المتعددة واسترداد Explorer في [قائمة تحقق الإصدار](docs/RELEASE_CHECKLIST.md).
