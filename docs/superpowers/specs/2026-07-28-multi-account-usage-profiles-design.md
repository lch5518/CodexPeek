# 다중 계정 사용량 프로필 설계

## 목적

사용자가 본인 소유의 여러 Codex 계정을 CodexPeek에 각각 로그인해 두고, 작업 표시줄
위젯과 플로팅 위젯에서 확인할 사용량 프로필을 선택할 수 있게 한다.

이 기능은 **사용량 모니터링만 전환**한다. 터미널, IDE, Codex 앱, WSL, 원격 호스트의
Codex 로그인이나 사용자 환경 변수는 변경하지 않는다. 한도에 따라 프로필을 자동 선택하거나
CLI 작업을 다른 계정으로 라우팅하는 기능도 제공하지 않는다.

## 핵심 사용자 경험

트레이 메뉴에 `사용량 프로필` 하위 메뉴를 추가한다.

```text
사용량 프로필
├─ ✓ 기본 Codex 계정    주간 28% 남음
├─ 개인                 주간 72% 남음
├─ 회사                 로그인 필요
├─ 계정 추가…
└─ 프로필 관리…
```

- 프로필 항목을 선택하면 캐시된 사용량을 즉시 표시하고 해당 프로필의 수동 갱신을 우선
  예약한다.
- UI에서는 `현재 계정`, `활성 계정`, `계정 전환` 대신 `사용량 프로필`, `표시 중인 프로필`,
  `사용량 보기`라는 표현을 사용한다.
- 플로팅 위젯에는 선택한 프로필 이름을 항상 표시한다. 공간이 제한된 작업 표시줄 위젯은
  본체 배치를 늘리지 않고 툴팁 첫 부분과 트레이 메뉴에 프로필 이름을 표시한다.
- 툴팁은 `사용량 프로필: 개인`과 `Codex CLI 로그인은 변경되지 않습니다`라는 의미를 현재
  UI 언어로 명확히 전달한다.
- 프로필 전환은 CodexPeek 설정만 바꾸며, 실행 중이거나 이후 실행되는 CLI·IDE 프로세스에
  영향을 주지 않는다.

## 프로필 모델과 저장 위치

### 시스템 프로필

기존 CodexPeek 동작은 삭제할 수 없는 `system` 프로필로 자동 승격한다. 이 프로필은 앱을
시작할 때 상속된 `CODEX_HOME`을 사용하고, 환경 변수가 없으면 Codex CLI의 기본
`%USERPROFILE%\.codex`를 사용한다. 기존 사용자는 설정 마이그레이션 뒤에도 같은 인증과
사용량을 보며 추가 로그인을 요구받지 않는다.

시스템 프로필의 표시명은 저장하지 않고 현재 UI 언어의 `기본 Codex 계정`에 해당하는
문구를 사용한다. 시스템 프로필은 이름 변경과 삭제를 허용하지 않는다.

### 관리 프로필

추가 계정은 CodexPeek가 관리하는 다음 경로에 독립된 Codex 홈을 사용한다.

```text
%APPDATA%\CodexUsageMonitor\profiles\profile-0001\codex-home\
```

설정에는 사용자 지정 표시명과 `profile-0001` 형태의 내부 식별자만 저장한다. 실제 경로는
설정 루트와 식별자로부터 계산하며 임의의 절대 경로는 받거나 저장하지 않는다. 프로필 번호는
설정의 단조 증가 카운터에서 할당하고 삭제된 번호를 재사용하지 않는다.

표시명은 앞뒤 공백을 제거한 뒤 1~40자의 유니코드 문자열만 허용한다. 제어 문자, 경로
구분자, `.` 또는 `..` 전체 일치, Rust 표준 라이브러리의 소문자 변환 뒤 중복되는 이름은
거절한다. 유니코드 정규화만을 위한 새 의존성은 추가하지 않는다.
표시명은 경로, 명령줄 또는 환경 변수 이름에 사용하지 않는다. 전체 프로필 수는 시스템
프로필을 포함해 8개로 제한한다.

관리 프로필의 인증은 Codex CLI가 해당 `CODEX_HOME` 아래에 직접 저장한다. CodexPeek은
`auth.json`을 열거나 파싱하거나 복사하지 않는다. 관리 프로필용 app-server는
`cli_auth_credentials_store = "file"` 설정 오버라이드를 사용해 인증이 프로필 디렉터리 밖의
OS 키링과 섞이지 않게 한다. 시스템 프로필에는 이 오버라이드를 적용하지 않아 사용자의 기존
Codex 설정을 보존한다.

## 설정 스키마와 마이그레이션

설정 스키마 버전을 올리고 다음 의미의 필드를 추가한다.

- 관리 프로필 목록: 내부 식별자와 사용자 지정 표시명
- 선택한 사용량 프로필 식별자
- 다음 프로필 번호

기존 스키마를 읽으면 빈 관리 프로필 목록, 선택 프로필 `system`, 다음 번호 `1`로 명시적으로
마이그레이션한 뒤 기존의 원자적 저장 절차로 기록한다. 선택 식별자가 없거나 중복 식별자,
잘못된 표시명, 프로필 수 초과, 역행한 다음 번호가 발견되면 설정 전체를 조용히 부분 적용하지
않는다. 기존 손상 파일 백업과 안전한 기본값 복구 정책을 따른다.

마지막 정상 사용량과 폴링 오류는 인증 설정 파일에 영속화하지 않고 런타임 메모리에 프로필별로
보관한다. 앱을 다시 시작하면 선택 프로필을 먼저 조회하고 나머지를 순차 조회한다.

프로필 메타데이터 변경과 일반 설정 저장이 서로 오래된 `Settings`를 덮어쓰지 않도록 모든 설정
쓰기는 하나의 순서가 보장된 백그라운드 작업 큐를 통과한다. 프로필 추가·이름 변경·선택·삭제는
저장 완료 결과를 UI 런타임에 돌려주며, UI 스레드는 디렉터리 I/O나 설정 파일 쓰기를 기다리지
않는다.

- 추가는 빈 관리 디렉터리를 만든 뒤 후보 설정을 원자적으로 저장한다. 저장에 실패하면 아직
  로그인을 시작하지 않은 빈 디렉터리만 검증 후 제거하고 런타임 목록에 추가하지 않는다.
- 이름 변경과 선택은 후보 설정 저장이 성공한 뒤 런타임 상태를 커밋한다.
- 삭제는 프로필 작업을 먼저 중단하고 관리 디렉터리를 같은 부모 아래의 내부 삭제 대기 이름으로
  원자 이동한 뒤, 해당 프로필을 제거한 후보 설정을 저장한다. 저장 실패 시 원래 이름으로
  되돌리고, 저장 성공 뒤 삭제 대기 디렉터리를 제거한다.
- 저장 성공 뒤 최종 디렉터리 제거만 실패하면 프로필은 설정에서 제거된 상태를 유지하고, 검증된
  삭제 대기 디렉터리를 다음 시작 때 다시 정리한다. 삭제 대기 이름과 경로는 로그에 남기지 않는다.

이 트랜잭션은 현재 `AsyncSettingsWriter`와 별개로 경쟁하는 두 번째 writer를 만들지 않고, 기존
writer를 결과 응답과 파일 작업 명령을 지원하도록 확장하거나 하나의 조정자로 대체한다.

## app-server 프로세스 경계

`ProcessGuard`, Job Object, 숨김 실행, 시간 제한, JSONL 프레임 크기 제한은 그대로 유지한다.
프로세스 시작 API에는 검증된 프로필 실행 문맥을 전달한다.

- 시스템 프로필: 현재 환경을 그대로 상속
- 관리 프로필: 해당 자식 app-server 명령에만 `CODEX_HOME=<계산된 경로>`를 주입하고 파일 기반
  인증 저장소 설정을 오버라이드

CodexPeek 프로세스의 환경, Windows 사용자 환경 레지스트리, `PATH`, 기본
`%USERPROFILE%\.codex`, IDE 설정을 수정하지 않는다. `SetEnvironmentVariable`,
`WM_SETTINGCHANGE`, 인증 파일 교체, 디렉터리 junction·symlink 전환 방식은 사용하지 않는다.

관리 프로필 경로는 반드시 설정 루트 아래의 예상 절대 경로인지 확인한다. 프로필 생성·삭제에서
경로 구분자, `..`, reparse point를 통한 루트 탈출을 거절한다. CLI 후보 탐색과 버전 확인은
기존 경로를 사용하며, 프로필은 app-server 실행 환경에만 영향을 준다.

## 계정 추가와 로그인 흐름

1. 사용자가 `계정 추가…`를 선택한다.
2. 네이티브 입력 창에서 표시명을 받아 검증한다.
3. 설정에 관리 프로필을 추가하고 전용 디렉터리를 만든다.
4. 워커 스레드가 해당 프로필 문맥으로 app-server를 시작하고 기존
   `account/login/start` ChatGPT 브라우저 로그인을 수행한다.
5. CodexPeek은 app-server가 반환한 검증된 로그인 URL만 연다. URL을 수정해 특정 계정을
   강제로 선택하지 않는다.
6. 로그인 완료 뒤 사용량을 즉시 조회하고 성공하면 새 프로필을 표시 프로필로 선택한다.

브라우저에 이미 다른 ChatGPT 계정이 로그인되어 있을 수 있으므로 로그인 시작 전에
`브라우저에서 사용할 계정을 확인하세요`라는 현지화 안내를 표시한다.

CodexPeek은 계정 ID나 이메일을 읽지 않으므로 두 프로필이 실제로 서로 다른 계정인지 확인할 수
없다. 동일한 ChatGPT 계정을 여러 표시명으로 로그인하는 것도 기술적으로 허용되며, 프로필 이름과
브라우저에서 선택한 계정의 대응은 사용자가 확인해야 한다.

로그인이 취소되거나 실패해도 프로필과 디렉터리를 자동 삭제하지 않는다. 프로필은 `로그인 필요`
상태로 남기고 사용자가 다시 로그인하거나 명시적으로 삭제할 수 있게 한다. 이 정책은 부분적으로
기록된 인증 데이터를 추측하거나 무리하게 정리하지 않고 외부 인증 실패에 안전하게 대응한다.

로그인 대기 중에도 UI 스레드를 막지 않는다. 로그인과 폴링은 공통 app-server 작업 게이트를
사용하므로 로그인 세션이 진행되는 동안 다른 프로필의 새 폴링은 대기하고 마지막 정상 사용량을
계속 표시한다.

## 폴링과 상태 전이

프로필별로 독립된 `PollState`를 두고 하나의 조정자가 모든 app-server 작업을 직렬화한다.
프로필마다 provider를 독립 실행해 동시에 RPC를 시작하는 구조는 사용하지 않는다.

- 앱 시작 시 선택 프로필을 먼저 조회한 뒤 나머지 프로필을 순서대로 조회한다.
- 자동 갱신 주기는 각 프로필의 마지막 시도 시각을 기준으로 적용한다.
- 실패 백오프 1/2/4/8/15분과 마지막 정상 사용량 보존 정책은 프로필별로 유지한다.
- 수동 갱신 10초 쿨다운은 전체 app-server 작업에 적용하고, 선택 프로필을 대기열 앞으로 옮긴다.
- 표시 프로필을 바꾸면 캐시된 상태를 즉시 렌더링하고, 캐시가 없으면 `갱신 중` 또는
  `로그인 필요`를 표시한다.
- 한도 잔량, 오류 또는 초기화 시각을 근거로 표시 프로필을 자동 변경하지 않는다.

한 프로필의 인증 만료나 응답 오류는 다른 프로필의 상태와 백오프에 영향을 주지 않는다.
연속적인 외부 실패가 있어도 조정자 스레드는 다음 기한이 된 프로필을 계속 처리한다.

## 프로필 관리

관리 화면은 표시명 변경, 다시 로그인, 로그아웃, 삭제만 제공한다.

- 이름 변경은 표시명만 바꾸며 디렉터리와 내부 식별자는 유지한다.
- 다시 로그인은 해당 프로필의 기존 `account/login/start` 흐름을 사용한다.
- 로그아웃은 프로필 문맥으로 `account/logout` RPC를 호출한다. 실패하면 로그인 상태를 성공으로
  가장하지 않고 안전한 오류만 표시한다.
- 삭제는 복구 불가능한 로컬 인증·설정·세션 삭제임을 확인받는다. 선택 프로필이면 먼저
  `system`으로 표시를 전환하고 실행 중 작업을 종료한 다음, 계산된 관리 경로가 정확히 프로필
  루트 내부이고 reparse point가 아님을 재검증한 뒤 그 디렉터리만 삭제한다.
- 삭제 중 오류가 나면 설정 목록에서 먼저 제거하지 않는다. 사용자가 재시도할 수 있도록
  프로필을 유지하고 안전한 오류를 표시한다.

시스템 프로필은 삭제·이름 변경할 수 없으며 기존의 로그인 및 인증 갱신 동작만 제공한다.

## 개인정보와 진단

`account/read`는 지금처럼 로그인 유형만 즉시 역직렬화한다. 이메일, 계정 ID, 사용자 ID,
토큰, 원본 RPC payload를 새 DTO, 설정, 로그, 오류 또는 테스트 fixture에 추가하지 않는다.

진단은 다음처럼 안정적인 분류만 보고한다.

- 프로필 설정 유효 여부
- 설정된 프로필 개수
- 선택 프로필이 조회 가능한지 여부
- 프로필별 결과를 합치지 않은 `ok`, `login_required`, `request_failed` 개수

사용자 지정 표시명, 내부 식별자, 프로필 경로, 계정 정보는 진단 로그에 기록하지 않는다.
`--diagnose`도 인증 파일은 프로필별 존재 여부를 집계할 수만 있고 내용을 읽지 않는다.

## 오류 처리

- 잘못된 표시명, 프로필 수 초과, 중복 프로필은 사용자 입력 오류로 즉시 거절한다.
- 디렉터리 생성, 설정 저장, app-server 시작, 브라우저 로그인 실패는 프로필 간 상태를
  섞지 않고 기존 표시 프로필과 마지막 정상 사용량을 유지한다.
- 표시 프로필 설정 저장이 실패하면 UI 선택을 커밋하지 않고 이전 프로필을 유지한다.
- 지원되지 않는 Codex CLI에서는 관리 프로필 로그인을 시작하지 않고 기존 안정 오류를 표시한다.
- 프로필 경로 검증 실패는 내부 경로를 노출하지 않는 안전 오류로 처리하고 파일 작업을 하지 않는다.
- 앱 종료 시 대기 중 로그인과 폴링을 취소하고 모든 app-server 자식 프로세스 트리를 기존
  Job Object 경계로 정리한다.

## 테스트 전략

### 단위 테스트

- 표시명 정규화, 중복, 길이, 제어 문자, 경로 문자 검증
- 프로필 ID 할당, 최대 개수, 시스템 프로필 불변 조건
- 기존 스키마에서 `system` 프로필로의 결정적 마이그레이션과 손상 설정 복구
- 관리 경로가 설정 루트 밖으로 나가지 않는지와 reparse point 거절
- 시스템·관리 프로필별 app-server 환경 및 인증 저장소 인자 구성
- 프로필별 마지막 정상값, 백오프, 선택 우선순위, 전체 수동 갱신 쿨다운
- 표시 전환 저장 실패 시 이전 상태 복원
- 동적 트레이 메뉴 명령 ID가 정확한 프로필 식별자로 변환되는지 검증
- 로그·진단·설정 직렬화에 금지된 계정 필드와 프로필 이름·경로가 포함되지 않는지 검증

### 통합 성격 테스트

trait 기반 가짜 provider와 파일 저장소를 사용해 여러 프로필을 결정적으로 검증한다.

- 선택 프로필 우선 조회 뒤 직렬 라운드로빈 수행
- 한 프로필의 timeout·인증 만료가 다른 프로필 상태를 손상시키지 않음
- 로그인 성공·취소·실패 후 상태 전이
- 삭제 실패 시 설정과 디렉터리 상태 보존
- 종료 시 실행 중 프로필 작업과 자식 프로세스 정리

실제 계정, 실제 `auth.json`, 실제 시간 지연에는 의존하지 않는다.

### Windows 수동 검증

- Windows 10/11과 100/125/150/200% DPI에서 프로필 이름과 메뉴 표시
- 긴 40자 표시명, RTL 언어, 다중 모니터, Explorer 재시작, 자동 숨김 작업 표시줄
- 브라우저에 다른 계정이 로그인된 상태에서 계정 추가·취소·재로그인
- Codex CLI 누락·업데이트·로그아웃·인증 만료 상태
- 프로필 전환 전후로 터미널과 VS Code의 Codex 로그인 상태가 변하지 않는지 확인
- 앱 종료 중 로그인 대기와 RPC timeout에서 자식 프로세스가 남지 않는지 확인

## 문서와 현지화

모든 새 사용자 문구는 `localization.rs`에 지원 언어 전체로 추가한다. README와 설치 문서에는
다중 사용량 프로필이 CodexPeek 표시만 바꾸며 CLI·IDE 계정은 변경하지 않는다고 명시한다.
SECURITY.md에는 프로필별 `CODEX_HOME`, 파일 기반 인증 저장소, 인증 파일 비열람 경계를
추가한다. 설정 스키마 변경과 삭제 동작은 릴리스 노트와 체크리스트에 반영한다.

## 제외 범위

- 터미널, IDE, Codex 앱, WSL, Remote SSH, Dev Container의 계정 전환
- Windows 사용자·시스템 `CODEX_HOME` 또는 `PATH` 변경
- 기본 `auth.json` 교체, 인증 파일 복사·가져오기·내보내기
- 계정 이메일·ID 자동 표시
- 한도 기반 자동 계정 선택, 자동 로테이션, CLI 작업 라우팅
- 여러 계정 사용량 합산 또는 결제·구독 관리
- 임의의 외부 Codex 홈 경로 등록

## 선택 근거와 대안

시스템 전체 계정 전환은 실행 중인 프로세스가 기존 환경을 유지하고 IDE마다 Codex 실행 경계가
달라 사용자가 실제 작업 계정을 오인할 위험이 크다. 기본 인증 파일 교체는 토큰을 직접 다루고
refresh token과 동시 실행 충돌을 일으킬 수 있어 프로젝트 보안 경계와 맞지 않는다.

선택한 설계는 app-server 자식 프로세스만 프로필별로 격리한다. 따라서 기존 Codex CLI의 인증
책임을 그대로 위임하면서 CodexPeek의 역할을 사용량 관찰로 제한하고, 외부 도구에 예측하지 못한
부작용을 만들지 않는다.
