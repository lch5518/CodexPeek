# 위젯 호버 툴팁 초기화 시각 설계

## 목적

작업 표시줄 위젯의 호버 툴팁만 보고도 Codex 사용량임을 알 수 있게 하고, 상대적인
초기화 잔여 시간 대신 실제 초기화 날짜와 시각을 표시한다.

## 표시 계약

사용량이 있을 때 한국어 툴팁은 다음 형식을 사용한다.

```text
Codex 7일 사용량
현재 사용량: 8%
남은 사용량: 92%
초기화 시각: 2026-07-27 (월) 03:00
상태: 안정 · 자동 갱신 중
```

영어는 첫 줄을 `Codex 7d usage`, 초기화 줄을
`Reset at: 2026-07-27 (Mon) 03:00`으로 표시한다. 사용량이 없을 때도 첫 줄은
`Codex 사용량` 또는 `Codex usage`로 표시한다.

날짜는 `YYYY-MM-DD (요일) HH:mm` 형식이며 Windows 현재 시간대와 DST 규칙을 따른다.
한국어 요일은 `일`부터 `토`, 영어 요일은 `Sun`부터 `Sat`까지 사용한다. 초기화
타임스탬프가 없거나 현지 시각으로 변환할 수 없으면 `초기화 시각 없음` 또는
`Reset unavailable`을 표시한다. 이미 지난 타임스탬프도 절대 날짜와 시각으로 표시한다.

## 구현 경계

- 기존 `windows` crate에 `Win32_System_Time` 기능만 추가하며 새 날짜 crate는 추가하지 않는다.
- Win32 경계는 `SystemTime`을 Windows 현지 달력 구성 요소로 변환하고, 도메인 계층은
  구성 요소의 검증과 언어별 문자열 형식을 담당한다.
- `UsageRowView.reset_text` 필드 이름은 유지하되 값의 의미를 상대 잔여 시간에서 절대
  초기화 시각으로 변경한다.
- 공개 `UsageWindow::remaining_label`은 호환성을 위해 유지하지만 위젯에서는 사용하지 않는다.
- 폴링, RPC, 설정 스키마, 작업 표시줄 본체의 짧은 레이블은 변경하지 않는다.

## 오류 처리와 검증

Win32 변환은 Unix epoch 이전 값, 산술 오버플로, 잘못된 달력 구성 요소를 안전하게
거절한다. 변환 오류는 사용자에게 내부 오류를 노출하지 않고 기존 초기화 시각 없음
문구로 축약한다.

단위 테스트는 양 언어 형식, 요일 매핑, 구성 요소 검증, FILETIME 변환 경계, Codex 제목,
데이터 없음 상태와 초기화 시각 툴팁을 검증한다. 전체 Rust 검사와 Windows 수동 호버
확인을 함께 수행한다.
