# Usage Profile Dialog Centering Design

## Goal

사용량 프로필 관리 흐름에서 표시되는 관리창, 추가창, 로그인·삭제 확인창,
유효성 경고 및 작업 오류창을 사용자가 작업 중인 모니터의 작업 영역 중앙에 표시한다.

## Placement policy

- 관리창은 열기 요청 시점에 마우스 커서가 있는 모니터의 `rcWork` 중앙에 표시한다.
- 추가창은 살아 있는 관리창이 위치한 모니터의 `rcWork` 중앙에 표시한다.
- 프로필 관련 `MessageBoxW`는 유효하고 크기가 있는 owner의 모니터 중앙에 표시한다.
  owner가 숨김 `(0, 0)` 창이거나 유효하지 않으면 현재 커서 모니터를 사용한다.
- 작업 영역보다 큰 창은 크기를 바꾸지 않고 작업 영역의 좌상단에 맞춘다.
- 창이 열린 뒤 모니터를 옮겨도 자동으로 다시 중앙 정렬하지 않는다.
- 모니터 조회, 위치 이동 또는 훅 설치가 실패하면 기존 Windows 기본 위치를 사용한다.
  위치 실패 때문에 대화상자 표시나 프로필 작업을 실패시키지 않는다.

## Architecture

중앙 좌표 계산은 플랫폼 핸들과 분리된 순수 계약으로 둔다. 네이티브 계층은 커서 또는
owner로 대상 모니터를 선택하고 `GetMonitorInfoW`의 작업 영역과 실제 `GetWindowRect`
크기를 계산 계약에 전달한다. 커스텀 창은 `ShowWindow` 전에 `SetWindowPos`로 옮기며,
DPI 전환으로 외곽 크기가 바뀌는 경우 한 번 더 계산한다.

`MessageBoxW`는 좌표 인자를 제공하지 않으므로 호출 동안 현재 UI 스레드에만 `WH_CBT`
훅을 설치한다. 훅은 최초 `HCBT_ACTIVATE` 대상만 중앙으로 옮긴 뒤 요청을 소비하며,
RAII guard가 모든 반환 경로에서 훅과 스레드 로컬 상태를 복원한다. 기존 확인 문구,
버튼, 반환값, owner 모달 동작은 유지한다.

## Safety boundaries

- 훅 콜백은 Rust 참조를 중첩 메시지 루프에 유지하지 않고 복사 가능한 좌표 값만 사용한다.
- 훅 콜백은 panic을 FFI 경계 밖으로 전달하지 않는다.
- 기존 관리·추가창 재진입 차단, owner 복원, `GWLP_USERDATA` 정리 순서를 유지한다.
- UI 스레드에 파일·설정·RPC I/O를 추가하지 않는다.
- Codex CLI/IDE 로그인 상태, 인증 파일, 프로필 저장 스키마는 변경하지 않는다.
- 새 의존성을 추가하지 않고 기존 `windows` 크레이트 기능만 사용한다.

## Verification

순수 테스트는 일반·음수 좌표 모니터, 작업 표시줄 제외, 홀수 크기, 초과 크기와
owner/커서 폴백을 검증한다. 상태 테스트는 CBT 요청의 설치, 한 번 소비, 중첩 복원과
해제를 검증한다. 회귀 테스트는 관리창이 Cursor 정책, 추가창이 Owner 정책을 사용하고
모든 프로필 확인·오류 경로가 중앙 메시지 래퍼를 소비하는지 확인한다.

수동 검증은 Windows 10/11의 100/125/150/200% DPI, 좌우·상하 다중 모니터,
각 모니터에서 관리→추가→경고/확인 흐름, 키보드 취소, RTL 언어를 포함한다.
