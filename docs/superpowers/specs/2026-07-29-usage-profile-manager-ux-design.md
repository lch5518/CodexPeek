# 사용량 프로필 관리 창 UI/UX 개선 설계

## 상태

- 설계 승인일: 2026-07-29
- 대상 브랜치: `feat/multi-account-usage-profiles`
- 대상 플랫폼: Windows 10/11 x64 네이티브 Win32 UI

## 목적

사용량 프로필 추가 진입점을 관리 창 한 곳으로 모아 트레이 메뉴의 중복을 없애고, 관리 창의
정보 구조와 종료 동작을 단순화한다. 동시에 삭제할 수 없는 시스템 프로필도 사용자가 알아보기
쉬운 이름으로 변경할 수 있게 하되, 관리 창에서만 이 프로필이 기본 계정임을 명확히 표시한다.

## 목표

- 트레이의 `사용량 프로필` 하위 메뉴에서 `사용량 프로필 추가` 항목을 제거한다.
- 프로필 추가는 `사용량 프로필 관리` 창의 계정 목록 아래 `+` 버튼에서만 시작한다.
- `+` 버튼은 별도의 작은 이름 입력 창을 열며, 이름 입력과 추가 확인을 관리 창의 rename 입력과
  분리한다.
- 관리 창 하단의 `닫기` 버튼을 제거하고 제목 표시줄 `X`와 `Esc`만 종료 수단으로 사용한다.
- 시스템 프로필의 이름 변경을 허용한다.
- 시스템 프로필의 사용자 지정 이름은 트레이와 위젯에서 그대로 표시하고, 관리 목록에서만
  `<사용자 지정 이름> (<지역화된 기본 계정>)`으로 표시한다.
- 기존 설정, 인증 격리, 비동기 settings/poller worker 경계와 터미널·IDE 비변경 계약을 보존한다.

## 비목표

- 관리 창을 장시간 유지되는 모델리스 창이나 실시간 대시보드로 재작성하지 않는다.
- 한 번에 여러 프로필을 연속 편집하는 batch UI를 추가하지 않는다.
- 시스템 프로필의 삭제 또는 로그아웃을 허용하지 않는다.
- 시스템 프로필 사용자 지정 이름을 초기화하는 별도 `기본값 복원` 기능을 추가하지 않는다.
- 프로필 자동 선택, 사용량 기반 순환 또는 CLI·IDE 계정 전환을 추가하지 않는다.

## 접근 방식 비교

### 1. 별도 추가 창과 기존 단일 액션 경계 유지 — 선택

관리 창 목록 아래 `+`를 누르면 소유형 modal 이름 입력 창을 연다. 취소하면 관리 창으로 돌아가고,
확인하면 검증된 `Add` 액션 하나를 반환한 뒤 기존 비동기 저장 경계를 사용한다.

- 장점: rename과 add 입력 상태가 섞이지 않는다.
- 장점: 현재의 “UI는 타입 액션만 반환하고 I/O는 worker에서 수행” 계약을 유지한다.
- 단점: 추가 확인 후에는 다른 mutation과 마찬가지로 관리 창이 닫힌다.

### 2. 관리 창 내부 add 모드

`+` 클릭 시 목록 선택을 해제하고 기존 이름 입력을 add 용도로 전환할 수 있다. 창을 추가로 만들지
않지만 rename/add 모드, 확인·취소 버튼과 포커스 상태가 늘어나 사용자가 현재 모드를 혼동할 수 있다.

### 3. 실시간 모델리스 관리 창

작업 완료 이벤트를 받아 목록을 즉시 갱신하면 관리 창을 계속 열어 둘 수 있다. 그러나 HWND 수명,
settings worker 이벤트, 종료·Explorer 복구와 동기화해야 하므로 이번 UX 정리 범위를 크게 넘는다.

## 트레이 메뉴

`사용량 프로필` 하위 메뉴는 다음 순서를 사용한다.

```text
사용량 프로필
├─ 기본 또는 사용자 지정 시스템 프로필
├─ 관리 프로필 1
├─ 관리 프로필 2
└─ 사용량 프로필 관리…
```

- `사용량 프로필 추가…` 정적 항목을 렌더링하지 않는다.
- 팝업 수명 동안 유지되는 동적 프로필 선택 ID `1000..=1007` 계약은 변경하지 않는다.
- `사용량 프로필 관리…`는 현재와 같이 타입 지정 `OpenManageUsageProfiles` 액션을 반환한다.
- 기존 공개 enum이나 명령 ID의 제거가 불필요한 호환성 위험을 만들면 내부 호환용으로 남길 수 있지만,
  실제 메뉴와 사용자 입력 경로에서는 접근할 수 없어야 한다.

## 관리 창 레이아웃과 동작

### 계정 목록

- 계정 목록은 현재처럼 시스템 프로필과 모든 관리 프로필을 표시한다.
- 목록 바로 아래 왼쪽에 작은 `+` 버튼을 배치한다.
- `+` 버튼의 화면 텍스트는 `+`로 유지하고, 지역화된 `사용량 프로필 추가` 설명을 tooltip 또는
  동등한 접근성 이름으로 제공한다.
- 프로필 수가 시스템 포함 8개이거나 mutation이 진행 중이면 `+`를 비활성화한다.
- 목록 선택 변경은 기존처럼 이름 입력과 작업 버튼 상태를 현재 프로필에 맞춘다.

### 이름과 작업 버튼

- 기존 이름 입력은 선택한 프로필의 rename 전용으로 사용한다.
- 하단 작업 버튼은 `이름 변경`, `로그인`, `로그아웃`, `삭제`만 유지한다.
- 기존 `추가` 버튼과 `닫기` 버튼은 생성하지 않는다.
- 제목 표시줄 `X`와 `Esc`는 액션 없이 관리 창을 닫는다.
- `Enter`는 기존 안전 정책대로 암묵적인 destructive/default 작업을 실행하지 않는다.

### 액션 제출 후 창 수명

- 이름 변경·로그인·로그아웃·삭제와 마찬가지로 추가 액션을 제출하면 관리 창을 닫는다.
- 실제 파일, 설정, Codex RPC 작업은 기존 worker에서 비동기로 수행한다.
- 추가 이름 입력 창에서 취소하면 아무 액션도 만들지 않고 관리 창은 열린 상태로 돌아온다.

## 프로필 추가 창

`+` 버튼은 관리 창을 owner로 하는 작은 modal 입력 창을 연다.

- 제목: 지역화된 `프로필 추가`
- 컨트롤: 이름 label, 이름 edit, `추가`, `취소`
- edit 제한: 기존 프로필 이름 계약과 같은 최대 40 Unicode scalar, 최악의 경우 80 UTF-16 unit
- 초기 포커스: 이름 edit
- `Enter`: 유효한 이름이면 `추가`와 동일
- `Esc`, `취소`, 제목 표시줄 `X`: 액션 없이 닫고 관리 창으로 복귀
- 잘못된 이름: 지역화된 안전 경고를 표시하고 입력 창을 유지
- 확인 성공: 검증된 `ProfileDialogAction::Add(label)` 하나만 반환

추가 액션이 네이티브 중앙 dispatch 경계로 돌아온 뒤에는 기존 브라우저 계정 확인을 정확히 한 번
수행한다. 브라우저 확인을 취소하면 프로필만 로그인 필요 상태로 추가하고 Login 작업은 만들지 않는
기존 계약을 유지한다.

## 시스템 프로필 이름 모델

### 저장 형식

`UsageProfileCatalog`에 선택 필드 `system_label: Option<String>`을 추가한다.

- `None`: 현재 UI 언어의 `UsageProfileSystem` 지역화 문자열을 표시한다.
- `Some(label)`: 사용자가 저장한 이름을 모든 일반 프로필 표시 위치에서 사용한다.
- 기존 schema v2 파일은 `#[serde(default)]`로 `None`을 복구한다.
- 필드 추가는 안전한 기본값이 있는 additive 변경이므로 schema version은 올리지 않는다.
- 직렬화 시 `None`을 생략해도 되며, 한 번 이름을 바꾸면 검증된 값을 저장한다.

### 검증과 변경 규칙

- 시스템 프로필 rename은 기존 `normalize_profile_label` 규칙을 사용한다.
- 사용자 지정 시스템 이름은 관리 프로필 이름과 대소문자를 구분하지 않고 중복될 수 없다.
- 관리 프로필 add/rename도 저장된 사용자 지정 시스템 이름과 중복될 수 없다.
- `system_label`이 `None`일 때 사용하는 지역화 fallback 이름은 locale에 따라 달라지므로 저장 이름
  중복 검증에는 참여하지 않는다. 사용자가 fallback과 같은 문자열을 직접 저장하면 그때부터 사용자
  지정 이름으로 간주해 중복 검증에 참여한다.
- 시스템 프로필은 rename과 login만 허용한다.
- 시스템 프로필 logout과 delete는 계속 거부한다.
- rename 저장 실패 시 마지막 내구성 이름과 현재 화면을 유지하고 안전한 실패 이벤트만 노출한다.

### 표시 규칙

- 트레이 프로필 선택 메뉴: 사용자 지정 이름만 표시한다.
- 작업 표시줄 tooltip과 floating widget header: 사용자 지정 이름만 표시한다.
- 관리 목록: 사용자 지정 이름이 있으면
  `<사용자 지정 이름> (<지역화된 UsageProfileSystem>)`으로 표시한다.
- 사용자 지정 이름이 없거나 사용자 지정 이름이 현재 지역화된 기본 이름과 같으면 기본 이름을 한 번만
  표시해 `기본 계정 (기본 계정)` 같은 중복을 피한다.
- 관리 목록의 요약 상태는 현재처럼 이름 뒤에 표시하며, 기본 계정 표식은 이름 부분에만 포함한다.

## 컴포넌트 변경

### `src/profiles.rs`

- `UsageProfileCatalog`에 선택형 시스템 이름과 getter를 추가한다.
- `rename(System, label)`을 허용한다.
- 시스템 사용자 지정 이름을 포함해 전체 label 중복 검증을 수행한다.
- 시스템 delete는 기존처럼 `SystemProfileImmutable`을 반환한다.

### `src/profile_settings.rs`, `src/app.rs`

- 기존 correlated rename 요청과 단일 settings writer를 그대로 사용한다.
- 시스템 rename도 관리 rename과 같은 내구성 저장 성공/실패 이벤트 순서를 사용한다.
- `UsageProfileView`와 selected label 생성 시 저장된 시스템 이름을 우선한다.

### `src/windows/tray.rs`

- 하위 메뉴에서 정적 add 항목을 제거한다.
- manage 항목과 동적 선택 action mapping은 유지한다.

### `src/windows/profile_dialog.rs`

- 시스템 프로필의 `Rename`을 활성화한다.
- 관리 목록 전용 row label helper를 두어 기본 계정 표식을 UI 모델과 분리한다.
- add prompt의 확인·취소 결과를 순수 상태 함수로 테스트할 수 있게 한다.

### `src/windows/profile_dialog/platform.rs`

- 관리 창의 add/close 하단 버튼을 제거한다.
- 목록 아래 `+` 버튼을 만들고 별도 owned add prompt를 연다.
- 두 modal 모두 HWND user-data 정리, owner 활성 상태 복원, `X`·`Esc` 무동작 종료 계약을 유지한다.

### 지역화

- 추가 창의 `취소` 문구와 `+` 접근성 설명에 필요한 키를 12개 언어에 추가한다.
- 기존 `MenuAddUsageProfile`, `UsageProfileAddTitle`, `UsageProfileName`을 재사용할 수 있는 곳은
  재사용한다.
- 기본 계정 표식은 기존 `UsageProfileSystem`을 재사용해 별도 용어가 언어별로 어긋나지 않게 한다.

## 오류 처리와 보안 경계

- UI 스레드는 modal 표시와 검증된 타입 액션 반환만 수행한다.
- settings 저장, 프로필 홈 생성, 로그인과 사용량 RPC는 UI 스레드에서 실행하지 않는다.
- 오류에 프로필 경로, 계정 이메일·ID, 인증 파일 내용 또는 원본 RPC payload를 포함하지 않는다.
- 사용자 지정 시스템 이름은 표시 데이터이므로 `settings.json`에는 저장되지만 진단 로그에는 기록하지
  않는다.
- 이름 변경은 시스템 프로필의 기존 `CODEX_HOME`, 인증 파일 또는 terminal/IDE 로그인에 영향을 주지
  않는다.

## 테스트 전략

### 도메인과 설정

- 기존 schema v2 catalog에 `system_label`이 없어도 기본값으로 로드한다.
- 시스템 rename이 저장·재로드되고 선택 ID와 실행 context는 변하지 않는다.
- 시스템 이름과 관리 이름의 대소문자 무시 중복을 양방향으로 거부한다.
- 시스템 delete와 logout 제한은 유지한다.
- 저장 실패 시 마지막 내구성 시스템 이름을 보존한다.

### 트레이와 UI 모델

- 트레이 하위 메뉴에 add 항목이 없고 manage 항목은 한 번만 존재한다.
- 동적 프로필 ID mapping은 기존 identity를 유지한다.
- 트레이·위젯에는 사용자 지정 시스템 이름만 표시한다.
- 관리 row에만 기본 계정 표식이 붙고 기본 이름 중복은 없다.
- 시스템 선택 시 rename은 활성, logout/delete는 비활성이다.

### 네이티브 대화상자

- 관리 창 control 사양에 하단 add/close가 없고 목록 아래 `+`가 있다.
- 최대 개수와 pending 상태에서 `+`가 비활성이다.
- 추가 prompt 확인은 검증된 Add 액션을, 취소·`Esc`·`X`는 아무 액션도 만들지 않는다.
- 40 scalar 및 80 UTF-16 unit 경계를 보존한다.
- main/add modal의 cleanup과 owner restore가 모든 종료 경로에서 한 번만 수행된다.

## 승인 기준

- 트레이 `사용량 프로필` 하위 메뉴에 추가 항목이 없다.
- 추가는 관리 창 목록 아래 `+`에서만 시작할 수 있다.
- 관리 창에 하단 닫기 버튼이 없고 `X`·`Esc`가 안전하게 닫는다.
